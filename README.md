# Lumera — маркетплейс beauty-специалистов и студий

Полноценный full-stack проект (Next.js + PostgreSQL + Prisma). Брендинг временный (название **Lumera**, иконка) — заменяется в `public/icons`, `src/components/layout/logo.tsx`, `src/i18n/messages/*.json`.

> **Статус: этапы 1–4 реализованы в коде** (каталог, вход, запись, кабинеты мастера/клиента, регистрация мастера и студии, панель студии, подписки и платежи, Super Admin, управление фонами/логотипом/медиа). **Ничего из этого не запускалось целиком в среде разработки** (там нет доступа к npm и БД): первый запуск у вас — возможны ошибки сборки, присылайте логи. Не реализованы реальные платёжные провайдеры (нужны ваши ключи) — см. «Что осталось».

## Что вставить вам, чтобы сайт стал вашим

1. **Сервер и БД:** `.env` (`DATABASE_URL`, `APP_URL`, `AUTH_SECRET`, `CRON_SECRET`, SMTP, `STORAGE_*`) — см. разделы ниже.
2. **Логотип, фон главной (фото/видео), фон блока для мастеров, заголовки:** войдите как Super Admin → `/{locale}/admin/content`. Иконки приложения (PWA/favicon): замените файлы в `public/icons/`.
3. **Фото/видео мастеров и студий** мастера загружают сами в кабинете (`/dashboard/*`, `/studio-admin/*`).

## Карта мастеров (`/{locale}/map` и блок на главной)

Категория → (для тату и других — стиль/подкатегория) → мастера появляются на карте; один маркер на адрес (число = сколько мастеров там); список справа; «Поблизу мене» берёт геолокацию **в браузере** (на сервер не отправляется) и сортирует по расстоянию. Карта — Leaflet + OpenStreetMap, **ключ API не нужен**. Для большого трафика замените адрес тайлов в `src/components/map/map-explorer.tsx` на провайдера с ключом (MapTiler, Stadia и т.п.): публичные серверы OSM рассчитаны на умеренную нагрузку.

**Адреса и координаты:** при сохранении адреса студии, филиала или мастера координаты определяются геокодером (см. выше). Если адрес не нашёлся, мастер стоит в центре города — можно уточнить адрес в профиле. В демо-данных координаты сгенерированы.

## Последняя сборка: что добавлено

* **Правила и Конфиденційність** (`/terms`, `/privacy`, uk/en): ссылки в регистрации и футере; название владельца и почта подставляются из `/admin/content`; дата согласия хранится в `User.termsAcceptedAt`. **Тексты — шаблоны, их обязательно должен проверить юрист.** Нужны ваши реквизиты в админке.
* **Нижняя панель на телефоне** (Главная · Поиск · Карта · Кабинет/Вход, для мастера + «Кабінет майстра»), с учётом «чёлки» iPhone; на странице мастера — липкая кнопка «Записатися».
* **Плавность и лёгкость:** плавный скролл (выключается при «уменьшении движения»), двойной тап не увеличивает страницу (pinch-zoom для доступности остаётся), карта и её скрипты грузятся только при приближении к блоку, видео-фон не играет на телефонах (показывается постер) и при включённой экономии трафика, нижние секции главной не рендерятся, пока не нужны, экраны загрузки и ошибок.
* **Удаление аккаунта** (`/account` → «Безпека»): пароль + подтверждение; личные данные стираются, записи/платежи/отзывы остаются без ФИО. Заблокировано, пока есть будущие записи или своя студия (требование магазинов приложений).
* **Геокодирование адресов** (Nominatim/OSM, `GEOCODER_EMAIL` в `.env`): адрес студии, филиала и мастера теперь превращается в координаты → точные метки на карте. Если геокодер недоступен, мастер стоит в центре города. Нужно ≥ 1 мин. между массовыми запросами (политика Nominatim) — для больших объёмов используйте платный геокодер через `GEOCODER_URL`.

## Что осталось (честно)

* **Юридические тексты** — шаблоны, нужна проверка юриста.
* **Экспорт данных пользователя** (право на переносимость) и push-уведомления.
* **Платёжные провайдеры** Stripe / LiqPay / WayForPay: интерфейс, вебхуки, биллинг и тестовый провайдер готовы; адаптеры подключаются вашими ключами (`src/server/payments/registry.ts`). Автосписание с карты не реализовано (продление оплачивается кнопкой).
* Редактирование категорий/городов/стран, переводов и модерация профилей/портфолио в админке (данные в БД есть, экранов нет).
* Пропорциональный перерасчёт при смене тарифа и при росте команды в середине периода (новые места учитываются при следующем продлении; разовое подключение оплачивается отдельно).
* Сжатие фото/видео и удаление GPS из EXIF при загрузке; CSP с nonce; Redis для лимитов при нескольких серверах; e2e-тесты на устройствах.

## Архитектурные решения

| Решение | Почему |
|---|---|
| **Next.js 14 (App Router) + TypeScript**, один репозиторий, backend = Route Handlers/Server Actions поверх слоя `src/server` | SSR для SEO, одна кодовая база, бизнес-логика вынесена из UI (`src/server/*`), её можно позже вынести в отдельный сервис без переписывания |
| **PostgreSQL + Prisma** | Строгие связи, миграции, типобезопасность |
| **Защита от двойных броней на уровне БД** (`EXCLUDE USING gist`, см. `prisma/manual/`) | Только констрейнт БД защищает от гонок; проверка в коде — лишь удобство |
| **Деньги — целые minor units + код валюты** | Никаких float; несколько валют без переделки |
| **Тарифы — данные (`SubscriptionPlan`)**, не константы | Super Admin меняет цены без деплоя |
| **Права — один модуль `src/server/auth/permissions.ts`**, deny-by-default | Все проверки на сервере; покрыт тестами |
| **Платежи — интерфейс `PaymentProvider` + реестр** | Stripe / LiqPay / WayForPay подключаются добавлением файла, схема БД не меняется |
| **Хранилище — интерфейс `StorageProvider`** (S3-совместимое) | Реализация — этап 3 |
| **i18n — JSON-каталоги + `Language`/`Translation` в БД** | UI-строки в файлах, контент БД (города, категории) в `Translation` |
| **Только `@prisma/client`, `zod`, `lucide-react`, `clsx`, `tailwind-merge`** из runtime-зависимостей | Минимум зависимостей = меньше рисков при `npm install` |

### Роли и права

* **Платформенные роли** (`UserRole`): `CLIENT`, `MASTER`, `STUDIO_OWNER`, `SUPER_ADMIN`.
* **Роли внутри студии** (`StudioMember`): `OWNER`, `ADMIN`, `MASTER`. Власть в студии даёт **только активная запись `StudioMember`**, а не метка роли.
* `SUPER_ADMIN` получает только `admin:*` и не становится владельцем студии или мастером.
* Студия **не владеет** профилем мастера: доступ к нему scoped и действует, пока членство `ACTIVE`; загрузка в портфолио — только при `portfolioConsent`. После ухода мастера (`ENDED`) профиль, портфолио и отзывы остаются у мастера.
* Одна строка `StudioMember` на пару (студия, пользователь) на всю историю → повторное приглашение не списывает «подключение 99 ₴» второй раз.

Матрица прав и граничные случаи — в `tests/permissions.test.ts`.

## GitHub с телефона без перетаскивания файлов

1. На github.com создайте **приватный** репозиторий.
2. В репозитории: *Add file → Create new file*, в поле имени введите `.github/workflows/unzip.yml` (слэши создают папки сами), вставьте текст ниже, *Commit changes*:
```yaml
name: Unpack ZIP
on:
  push:
    paths:
      - '*.zip'
permissions:
  contents: write
jobs:
  unpack:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Unpack the uploaded ZIP into the repository root
        run: |
          if ! ls ./*.zip >/dev/null 2>&1; then echo "No zip here, nothing to do"; exit 0; fi
          ZIP=$(ls ./*.zip | head -n1)
          mkdir _tmp && unzip -q -o "$ZIP" -d _tmp
          TOP=$(ls _tmp | head -n1)
          if [ "$(ls _tmp | wc -l)" = "1" ] && [ -d "_tmp/$TOP" ]; then cp -a "_tmp/$TOP/." . ; else cp -a _tmp/. . ; fi
          rm -rf _tmp "$ZIP"
      - name: Commit the unpacked project
        run: |
          git config user.name "unzip-bot"
          git config user.email "bot@users.noreply.github.com"
          git add -A
          git commit -m "Unpack project" || echo "Nothing to commit"
          git push
```
3. *Add file → Upload files* → выберите `lumera.zip` с телефона → *Commit*. Через ~1 минуту во вкладке *Actions* пройдёт «Unpack ZIP», и в репозитории появятся все файлы и папки; архив удалится.
4. Дальше подключите репозиторий к хостингу, который собирает проект из `Dockerfile` (Railway, Render и подобные): добавьте PostgreSQL и в переменные окружения проекта пропишите `DATABASE_URL` (из добавленной базы), `APP_URL` (адрес сайта), `AUTH_SECRET` и `CRON_SECRET` (случайные строки от 32 символов), `SEED_DEMO=true`, `SEED_ADMIN_PASSWORD`, `SEED_DEMO_PASSWORD`. Папку `/app/uploads` подключите как постоянный том (или настройте `STORAGE_*` для S3/R2), иначе загруженные фото пропадут при перезапуске. Таблицы и демо-данные создаются автоматически при старте.
Файл `.env` в репозиторий не попадает (он в `.gitignore`) — секреты держите только в настройках хостинга.

## Самый простой запуск (с телефона, без папок)

Папки перетаскивать не нужно: на сервер заливается **один файл** (ZIP), дальше всё делает скрипт.

1. Арендуйте сервер (VPS) с Ubuntu: 2 ГБ RAM, 20+ ГБ диска (Hetzner, DigitalOcean и т.п.). Если нужен адрес `https://ваш-домен` и установка как приложение, направьте A-запись домена на IP сервера.
2. На телефоне поставьте приложение **Termius** (iOS/Android): подключитесь к серверу по SSH и через вкладку SFTP загрузите `lumera-v4.zip` в домашнюю папку.
3. В терминале Termius выполните по очереди:
```
curl -fsSL https://get.docker.com | sh
apt-get install -y unzip
unzip lumera-v4.zip && cd lumera
sh setup.sh                # без домена: http://IP-сервера:3000
# или: sh setup.sh ваш-домен.com   # с автоматическим HTTPS
```
4. Скрипт сам создаёт `.env` с надёжными секретами, собирает сайт, поднимает базу, создаёт таблицы, ограничения и демо-данные. Первый запуск 2–5 минут: `docker compose logs -f app`. В конце он напечатает пароль админа.
5. Откройте сайт, зайдите админом → «Вигляд сайту» и загрузите логотип, фото/видео.

Когда будете готовы к реальным данным: в `.env` поставьте `SEED_DEMO="false"` и `docker compose up -d`. Обновление сайта: заменить файлы новым архивом и `docker compose up -d --build`. Резервная копия базы: `docker compose exec db pg_dump -U lumera lumera > backup.sql`.

*Примечание:* этот режим создаёт таблицы командой `prisma db push` (без файлов миграций) — для первого запуска это нормально; для долгой эксплуатации переходите на `prisma migrate` (раздел ниже).

## Запуск локально

```bash
cp .env.example .env                  # затем отредактируйте (см. ниже)
docker compose up -d db               # PostgreSQL на localhost:5432
npm install                           # создаст package-lock.json
npx prisma migrate dev --name init    # создаёт таблицы и папку prisma/migrations
npm run db:constraints                # CHECK/EXCLUDE-констрейнты (двойные брони и др.) — идемпотентно
npm run db:seed                       # демо-данные
npm run dev                           # http://localhost:3000  → редирект на /uk
```

`AUTH_SECRET` сгенерируйте: `openssl rand -base64 48`.

**Важно про миграции:** в архиве нет `prisma/migrations`, потому что Prisma генерирует её, подключаясь к живой БД. Первая миграция создаётся командой `prisma migrate dev --name init` — **закоммитьте** получившуюся папку. После каждой новой миграции повторяйте `npm run db:constraints` (скрипт идемпотентный).

## Развёртывание на сервере

1. VPS с Docker, управляемый PostgreSQL (или контейнер с томом + бэкапы).
2. `.env` на сервере: боевые `DATABASE_URL`, `APP_URL` (https), `AUTH_SECRET`.
3. `docker build -t lumera .` → `docker run --env-file .env -p 3000:3000 lumera`.
4. Миграции: `npx prisma migrate deploy && npm run db:constraints` (один раз на релиз).
5. Reverse proxy (Caddy/Nginx) с HTTPS — **обязательно**: PWA и service worker работают только по HTTPS.
6. Rate limiting сейчас in-memory (один процесс); для нескольких инстансов нужен Redis (задача этапа 4).

| URL | Что |
|---|---|
| `/{uk,en}` | Главная: поиск, категории, популярные мастера и студии, рекомендации, города, преимущества, блок для партнёров |

| `/{locale}/partners` | Тарифы из БД (`SubscriptionPlan`) и формула цены студии — рассчитывается тем же кодом, что и биллинг |

**Параметры поиска:** `city, district, category, sub, date, time, priceMin, priceMax, rating, experience, gender, available, sort (rating|popularity|price|distance|nearest), type, lat/lng, page`. Разбор — `src/server/catalog/params.ts` (невалидное отбрасывается), Prisma-условия — `filters.ts`, пайплайн — `search.ts`.

**Что видно публично** (`src/server/catalog/visibility.ts`): профиль `PUBLISHED`, владелец не заблокирован и есть живая подписка (своя или подписка студии, где мастер активен). Это условие подмешивается в **каждый** запрос каталога первым (покрыто тестом).

**Свободное время** (`src/server/booking/slots.ts`): недельный шаблон + перерывы − дни-исключения − записи (с буфером), в часовом поясе города мастера, с учётом перехода на летнее время. Этот же модуль использует поиск («ближайший слот», фильтр даты/времени) и будет использовать бронирование в этапе 3.

## Шаг 3a: что где

| URL | Что |
|---|---|
| `/{locale}/register`, `/login`, `/forgot-password`, `/reset-password?token=`, `/verify?token=` | Аутентификация. Вход и регистрация возвращают на страницу, откуда пришёл пользователь (`next`, только внутренние пути) |
| `/{locale}/account` | Кабинет клиента: будущие записи (отмена, перенос), история и отзыв, избранное, уведомления, профиль, смена пароля |
| `/{locale}/account/reschedule/<id>` | Перенос записи (≥ 2 часов до начала) |
| `/{locale}/dashboard` | Кабинет мастера (пока раздел «Записи»): подтвердить / отменить / завершить визит |
| Профиль мастера | Виджет записи с реальными слотами выбранной услуги, кнопка «Избранное» |

**Как это защищено:**
* Пароли — scrypt; сессии — случайный токен в `httpOnly` cookie, в БД только его sha256; вход, регистрация, письма — rate limit; одинаковый ответ и время для неизвестной/заблокированной почты; сброс пароля завершает все сессии.
* Токены писем одноразовые (условный `UPDATE`), подтверждение почты — по `POST`, а не по ссылке (сканеры почты не «сжигают» токен).
* Права — только `can()/assertCan()` на сервере; чужие записи отвечают «не найдено».
* **Двойные записи:** слот проверяется движком расписания → advisory-lock на мастера → повторная проверка пересечений → вставка; последняя линия — EXCLUDE-констрейнт (`npm run db:constraints`).
* Отзыв — только на `COMPLETED` запись, один на запись (`bookingId UNIQUE`), 60 дней, **публикуется после модерации** (интерфейс модерации — этап 4; пока отзывы ждут в статусе `PENDING`).

**Письма.** Без `SMTP_HOST` письма печатаются в консоль сервера (dev): оттуда берите ссылки подтверждения и сброса. В production без SMTP письма отбрасываются и ничего не логируется.

**Демо-входы** (после `npm run db:seed`): `client1@lumera.test` (клиент), `<slug-мастера>@lumera.test`, например `olena-koval@lumera.test` (мастер), пароль — `SEED_DEMO_PASSWORD`. Все демо-аккаунты с подтверждённой почтой.

## Часть 4a: биллинг и Super Admin

**Подписка мастера:** `/{locale}/dashboard/subscription` — выбор тарифа (данные из `SubscriptionPlan`), оплата, статус, дата следующего списания, история платежей, отмена в конце периода / возобновление.

**Как платёж становится подпиской:** выбор тарифа → `Subscription(INCOMPLETE)` + `Payment(PENDING)` → редирект на провайдера → **вебхук** `POST /api/webhooks/<provider>` (проверка подписи по сырому телу → идемпотентная обработка → сверка суммы, валюты и id платежа) → `ACTIVE`, новый период. Профиль в каталоге появляется только после этого (`visibility.ts`).

**Жизненный цикл** (`src/server/billing/lifecycle.ts`, ежедневная задача `POST /api/cron/billing` с `Authorization: Bearer $CRON_SECRET`):
`ACTIVE` → за 3 дня напоминание → конец периода: `PAST_DUE` (создаётся платёж на продление, профиль виден) → +3 дня `GRACE` (профиль виден, **новые записи отключены**, 7 дней на оплату) → `EXPIRED` (профиль скрыт). Любая успешная оплата возвращает в `ACTIVE`. Отмена: доступ сохраняется до конца оплаченного периода. Демо-подписки (`isDemo`) задачей не затрагиваются.

**Тестовая оплата (только разработка):** `PAYMENT_PROVIDERS="test"` → страница `/{locale}/pay/test/<paymentId>` подписывает вебхук так же, как провайдер, и пропускает его через тот же код. В production страница недоступна (404), если не задан `ALLOW_TEST_PAYMENTS=true`. Это не имитация реальных денег и помечено в интерфейсе.

**Попробовать:** войдите как `olena-koval@lumera.test` → «Кабинет майстра» → «Підписка та платежі». У демо-мастеров демо-подписка; чтобы пройти оплату, зарегистрируйте нового мастера (шаг 3b) либо временно переведите демо-подписку в `CANCELLED`/`EXPIRED` в БД.

**Super Admin** `/{locale}/admin` (404 для всех остальных; права проверяются и в layout, и в каждом Server Action; каждое действие пишется в `AuditLog`):
* Обзор — клиенты, мастера, студии, записи за 30 дней, активные подписки, MRR, график дохода за 6 месяцев.
* Пользователи — поиск, блокировка/разблокировка (блокировка завершает сессии; себя и других админов блокировать нельзя).
* Отзывы — очередь модерации; после решения рейтинг пересчитывается только по опубликованным.
* Тарифы — цены, цена места, разовое подключение, доступность — без деплоя.
* Платежи и подписки — последние 50.
Вход: `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` из сида.

### Ограничения 4a (чего нет — прямо)

* **Stripe, LiqPay, WayForPay не реализованы** (явная ошибка `ProviderNotConfiguredError`) — интерфейс, реестр, проверка вебхуков и обработка готовы, нужен только адаптер провайдера и ваши ключи. Без реального провайдера в production оплата недоступна.
* **Автосписание с сохранённой карты не реализовано**: продление создаёт платёж `PENDING`, мастер оплачивает его кнопкой «Оплатить». Для Stripe Subscriptions/рекуррентов LiqPay/WayForPay потребуется адаптер.
* Смена тарифа на лету (апгрейд/даунгрейд с пропорциональным перерасчётом) не реализована: отмена в конце периода и выбор нового. Возвраты (`refunded`) только фиксируются.
* **Платежи студий** (база + места + 99 ₴ за подключение) — часть 4b: формула и расчёт готовы и покрыты тестами, но студий через интерфейс подписать пока нельзя.
* Админка: нет управления категориями/городами/странами, контентом главной, переводами и системными настройками, модерации профилей и портфолио, фильтров/экспорта в отчётах (часть 4b/после). Данные для них в БД уже есть.
* Баннер «ограничение функций» сейчас = запрет новых записей в `GRACE`; других ограничений нет.
* Не запускалось целиком: проверьте вебхуки и cron первым запуском и пришлите логи.

## Фото и видео, фоны сайта (управляется из админки)

* **Загрузка:** `POST /api/upload` (только вход, права по назначению, ≤105 МБ запрос, фото ≤10 МБ, видео ≤100 МБ, форматы JPG/PNG/WebP/AVIF/MP4/WebM, тип определяется по содержимому, SVG запрещён, ключ файла генерирует сервер, лимит запросов).
* **Хранилище:** если заданы `STORAGE_BUCKET`, `STORAGE_ACCESS_KEY_ID`, `STORAGE_SECRET_ACCESS_KEY`, `STORAGE_PUBLIC_BASE_URL` (+ `STORAGE_ENDPOINT` для R2/MinIO/B2) — S3-совместимое; иначе — папка `uploads/` на диске (подключите её как постоянный том), раздаётся через `/media/*` с поддержкой Range (нужно Safari для видео).
* **Фон главной:** `/{locale}/admin/content` (только Super Admin): фото или видео-фон (+ постер), затемнение, свои заголовок/подзаголовок для каждого языка, фоновое фото блока «для майстрів». Видео играет без звука в цикле; при включённом «уменьшении движения» показывается постер.
* **Главная в стиле портфолио-платформы:** полноэкранный hero, плитки категорий с реальными фото работ, «мозаика» новых работ, крупные плитки мастеров и студий.
* **Ограничения:** файлы не пережимаются и EXIF/GPS не вычищаются (нужен `sharp`/ffmpeg — отдельный шаг); перед загрузкой видео сожмите его (оптимально 720p–1080p, 5–15 с, до 8 МБ для мобильного интернета).

## Как расширять

* **Язык:** `src/i18n/config.ts` (TypeScript заставит заполнить `localeMeta`) → `messages/<код>.json` → `dictionaries.ts` → строка в `Language`. Тест `i18n.test.ts` проверяет, что ключи совпадают.
* **Страна/город/район/категория:** строки в БД (+ `Translation`); править код не нужно.
* **Валюта:** строка в `Currency`, цены — `ServicePrice` (по строке на валюту).
* **Платёжный провайдер:** реализовать `PaymentProvider`, зарегистрировать в `registry.ts`, добавить переменные в `env.ts`.

### Ограничения шага 3a (чего нет — прямо)

* **Нет регистрации мастера/студии и кнопки «Стать партнёром» → регистрация.** Кнопка ведёт на тарифы. Кабинет мастера работает только для демо-мастеров из сида (роль `MASTER` + профиль).
* В кабинете мастера пока только «Записи». Профиль, портфолио, услуги и цены, расписание/исключения, клиенты, отзывы, студии, подписка — шаг 3b/этап 4.
* **Студийный персонал не видит и не ведёт записи** своей команды (этап 4); записью управляет сам мастер.
* **Загрузки файлов нет** (аватар, портфолио) — шаг 3b.
* Автоподтверждение записей не настраивается: все новые записи `PENDING` до подтверждения мастером.
* При переносе записи собственное старое время считается занятым (выберите другое).
* Регистрация сообщает, что почта уже занята (так удобнее пользователю); вход и сброс пароля при этом не раскрывают существование аккаунта.
* Rate limit хранится в памяти процесса; для нескольких инстансов нужен Redis.
* Нет вспомогательных email-напоминаний «за день до записи» (нужен планировщик, этап 4).
* Страница входа не предлагает Google/Apple/Facebook (нет такого пункта в ТЗ как обязательного).
* Не запускалось целиком: `useFormState`/Server Actions/Prisma-запросы проверьте первым запуском и пришлите логи.

### Ограничения этапа 2 (чего нет — прямо)

* **Дополнительные параметры по категориям** (например, «стиль тату») не реализованы — есть общие подкатегории.
* Фильтры по стране в UI нет (активна одна страна), параметр `country` в URL работает.
* Расстояние считается от координат браузера (кнопка «Поблизу мене») до адреса мастера/студии, а если адреса нет — до центра города. В демо-данных координаты адресов сгенерированы.
* Сортировки в памяти (цена, расстояние, ближайшее время) работают по ≤500 кандидатам (≤200 для расчёта слотов). Для масштаба нужен предрасчёт/кэш — задача после этапа 4.
* «Ближайший слот» считается по самой короткой подходящей услуге мастера.
* Страницы читают БД на каждый запрос (`force-dynamic`): кэширование добавим вместе с админкой, чтобы правки её сбрасывали.
* Картинки — обычные `<img loading="lazy">` (демо — SVG-заглушки); `next/image` подключим вместе с реальным хранилищем.
* Карты нет: ссылка «Открыть на карте» ведёт на Google Maps (встраивание потребует CSP и ключей).
* Рабочие часы студии на её странице — огибающая графиков команды (у студии нет собственного расписания в схеме).
